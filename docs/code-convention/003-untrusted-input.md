# Convention 003: Documents Are Untrusted Input

- **Run LibreOffice only through the unoserver pool** ([ADR 004](../adr/004-unoserver-pool.md)): each instance on localhost only, with its own profile, no network access, a conversion timeout, recycling after a set number of conversions, and a supervisor that restarts it when it exits. Do not weaken the recycling or timeouts without an ADR.
- **Tell a PDF from a DOCX by its bytes,** never by the file name or the content type the client sent, and refuse anything else before converting or rendering it (`engine/checks/`). A PDF must start with `%PDF-`; a DOCX is a zip whose `[Content_Types].xml` names a Word document part, so a DOCM, DOTX, XLSX or PPTX is refused.
- **Open a DOCX with LibreOffice's DOCX import filter only,** never format detection, which would convert a `.doc`, RTF, HTML or plain text sent in its place.
- **Work in a per-job scratch directory and wipe it afterwards.**
- **Reject macro-enabled files, enforce file size and page limits, and guard against zip bombs** (DOCX is a zip). A DOCX whose `[Content_Types].xml` declares a VBA project, VBA data or ActiveX controls, or that holds a `vbaProject.bin` or `vbaData.xml` part anywhere, is refused before conversion (`engine/checks/docx_macros.py`). Before that, `engine/checks/docx_zip_limits.py` checks the zip headers (part count, unzipped size, expansion of each large part) and reads every part back within its declared size and checksum. The size limit (`DIPLEX_MAX_UPLOAD_BYTES`) is enforced by `api/upload_size_limit.py` on the declared Content-Length and again as the body arrives, so a chunked upload can't get past it.
- **Refuse a page whose image would be too large before rendering anything.** A PDF can declare any page size, and at 144 DPI a 200-inch page is a 2.5 GB bitmap. A side over 16,383 pixels (113.7 inches) is refused too, since WebP can't hold it ([WebP FAQ](https://developers.google.com/speed/webp/faq)). The limits are `MAX_PAGE_PIXELS` and `MAX_PAGE_SIDE_PIXELS` in `engine/pages/page_images.py`.
- **Never log document contents.** Each render job logs one line (`api/job_log/`): its ID, source type, size in bytes, page count, duration and outcome, and never the file name. An unexpected error logs its type and stack but not its message, which can quote the document, and the route answers it with a 500 so the server doesn't log it either.
